# v0.3.2 — Hermes Agent Compatibility Spec

**Status:** Accepted
**Drafted:** 2026-05-04
**Verified against Hermes source:** 2026-05-06 (commit `d514dd40` and earlier)
**Scope:** Make intern-os fully compatible with the latest Hermes Agent framework while preserving OpenClaw compatibility and a framework-agnostic core.

---

## TL;DR

intern-os is already a structurally valid Hermes skill — `intern-os/SKILL.md` uses Hermes' frontmatter shape (`name`, `description`, `version`, `metadata.hermes.tags`) and the `hermes skills install poktalabs/intern-os/intern-os` command works today. The work to "make it ready for Hermes" is **not a port** — it's surfacing three native Hermes mechanisms that the current SKILL.md sidesteps with hardcoded paths and manual copy steps. All three are additive, safely ignored by OpenClaw and Claude Code, and meaningfully reduce manual setup surface area.

---

## Current state

### What's good
- **Framework-agnostic core** lives at `intern-os/SKILL.md` + `intern-os/references/` + `intern-os/assets/templates/` + `intern-os/scripts/`. No Hermes-specific bindings in the body.
- **Adapter overlay pattern** (`adapters/{hermes,openclaw,claude-code,generic}/SETUP.md`) cleanly separates per-framework wiring from doctrine.
- **Frontmatter is Hermes-compatible**: `metadata.hermes.tags`, `metadata.hermes.related_skills` already present.
- **Bundled file layout** matches Hermes' auto-discovery convention (`references/`, `templates/`, `scripts/`, `assets/`) — Hermes lists these automatically when the skill activates (`skill_commands.py:206`).

### Friction points
- `~/.hermes/workspace/` and `~/.hermes/skills/intern-os/` are **hardcoded** in SKILL.md, IMPLEMENT.md, and `adapters/hermes/SETUP.md`. Breaks for users with non-default `HERMES_HOME`, profiles, or Docker layouts.
- `IMPLEMENT.md` at the repo root references `~/duki-admin/research/projects/intern-os/` — a path that exists only on the original author's machine. It also duplicates `adapters/hermes/SETUP.md`.
- The Hermes adapter SETUP.md tells users to manually `cp ~/.hermes/skills/intern-os/assets/WORKSTREAMS.md ~/.hermes/workspace/WORKSTREAMS.md` — but Hermes' auto-supporting-files mechanism would surface this without the copy.
- `tick` is required but never validated — users see cryptic shell errors instead of a clean "missing prerequisite" hint.

## Recommendation

Adopt the three Tier-A mechanisms only. Concretely:

### 1. Enrich `intern-os/SKILL.md` frontmatter

```yaml
---
name: intern-os
description: internOS Workstreams framework. Coordinates work across projects, tick.md tasks, communication threads, and filesystem workstreams.
version: 0.4.0
prerequisites:
  commands: [tick]            # advisory — surfaces setup note if missing
setup:
  help: "Install tick-md with `npm install -g tick-md`. Then run `hermes setup` to configure internos.workspace_path."
metadata:
  hermes:
    tags: [Workstreams, Project Management, Coordination]
    related_skills: []   # optional: [linear, notion] if those skills exist in target Hermes install
    config:
      - key: internos.workspace_path
        description: Path to the internOS workspace where projects/ lives
        default: "~/.hermes/workspace"
        prompt: internOS workspace directory
---
```

**Effect on each framework:**
- **Hermes:** prompts user during `hermes setup`, persists `internos.workspace_path` in `config.yaml`, injects resolved value into skill payload at activation, validates `tick` on PATH.
- **OpenClaw / Claude Code / generic:** silently ignore unknown frontmatter keys. No regression.

### 2. Audit hardcoded paths in SKILL.md body and templates

- Where the SKILL.md body references **bundled skill files**, switch to `${HERMES_SKILL_DIR}/...` (Hermes substitutes; other frameworks see literal — adapter SETUPs already give correct concrete paths).
- Where it references **the workspace**, change wording to "in the configured workspace" so the injected `[Skill config: internos.workspace_path = ...]` block becomes the source of truth.

### 3. Rewrite `adapters/hermes/SETUP.md`

- Remove the manual `cp .../assets/WORKSTREAMS.md .../workspace/WORKSTREAMS.md` step (auto-supporting-files makes the file visible without the copy).
- Add: `/intern-os` slash command works in any session after install.
- Add: `hermes setup` prompts for `internos.workspace_path` — no manual path editing required.
- Note that `prerequisites.commands: [tick]` will surface a setup hint if `tick` is missing.

### 4. Replace `IMPLEMENT.md`

It duplicates `adapters/hermes/SETUP.md` and references a non-existent path. Either:
- **Delete** (preferred — adapter SETUPs cover it), or
- **Rewrite to ~10 lines** pointing at `adapters/[framework]/SETUP.md`.

# SETUP — Hermes Agent Adapter

*internOS v0.3.2 | 2026-05-06*

Hermes Agent-specific setup for the internOS Workstreams framework.

---

## Prerequisites

- Hermes Agent installed and running
- `tick-md` CLI on PATH: `npm install -g tick-md`
- At least one platform configured (Telegram, Slack, Discord, etc.)

---

## Install

    hermes skills install poktalabs/intern-os/intern-os

For development, symlink instead:

    ln -s [intern-os-repo]/intern-os ~/.hermes/skills/intern-os

---

## Configure

Run `hermes setup` (or edit `~/.hermes/config.yaml`) and set:

- `internos.workspace_path` — path to the internOS workspace where `projects/` lives. Default: `~/.hermes/workspace`.

Hermes injects this value into the skill payload at activation as a `[Skill config: ...]` block, so the agent always has the resolved absolute path.

---

## Initialize the workspace

    mkdir -p ~/.hermes/workspace/projects/
    cd ~/.hermes/workspace/projects/
    mkdir my-project && cd my-project
    tick init
    tick agent register @bot --type bot --role engineer

> The `WORKSTREAMS.md` runtime guide is auto-listed as a supporting file when intern-os activates — no manual copy required.

---

## Activate

In any thread:

- Type `/intern-os` to load the skill explicitly, or
- Add `intern-os` to `agent.preloaded_skills` in `~/.hermes/config.yaml` to load it on every session.

---

    platforms:
      slack:
        enabled: true
        token: "${SLACK_BOT_TOKEN}"
        reply_to_mode: "first"

---

## Discord (optional)

In `~/.hermes/config.yaml`:

    platforms:
      discord:
        enabled: true
        token: "${DISCORD_TOKEN}"

Forum channels named `*-workstreams` work natively as workstream threads. The agent emits ACK before any file reads (LIGHT mode) — see SKILL.md.
